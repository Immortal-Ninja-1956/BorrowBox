## 1. Project Overview

BorrowBox is a peer-to-peer campus marketplace exclusively for VIT students, allowing them to list, browse, buy, and sell secondhand items with a built-in escrow-style deal flow (Interest → Ship → Deliver → Confirm → UPI Payment). The backend serves both the API and the built Vite SPA from a single Express process. Authentication is cookie-based JWT, restricted to `@vitstudent.ac.in` email addresses with mandatory email OTP verification before login.

## 2. Architecture

### Frontend

- **Framework**: React 19 SPA
- **Routing**: `wouter` v3 (`<Switch>` + `<Route>`) declared in `client/src/App.tsx`
- **State Management**: No global store. Server state via `@tanstack/react-query` through tRPC hooks. Local UI state via `useState`.
- **Theme**: `ThemeContext` wraps the app with dark mode default (`defaultTheme="dark" switchable`). Persists via `next-themes`.
- **tRPC Client**: Configured in `client/src/lib/trpc.ts`. Uses `httpBatchLink` pointed at `/api/trpc`.
- **Auth State**: `useAuth()` hook at `client/src/_core/hooks/useAuth.ts` — calls `trpc.auth.me` on mount to populate user.

**Page Routes:**

| Route | Component | Auth Required |
|---|---|---|
| `/` | Home | No |
| `/login` | Login | No |
| `/register` | Register | No |
| `/verify-email` | VerifyEmail | No |
| `/forgot-password` | ForgotPassword | No |
| `/reset-password` | ResetPassword | No |
| `/marketplace` | Marketplace | No (guest browsing enabled) |
| `/item/:id` | ItemDetail | No (actions gated) |
| `/create-post` | CreatePost | Yes (hard redirect) |
| `/edit-post/:id` | EditPost | Yes |

| `/admin` | AdminDashboard | Yes + admin role |
| `/confirm/:dealId` | BuyerConfirmation | Yes |
| `/404` | NotFound | No |

### Backend

- **Server**: Single Express process. In dev, Vite runs in middleware mode (`setupVite()`). In prod, serves `dist/public` as static.
- **API**: All business logic exposed via tRPC at `/api/trpc`. No REST endpoints except `POST /api/upload`.
- **DB Layer**: `server/db.ts` — plain async functions wrapping Drizzle queries. Lazy singleton connection via `getDb()`. Throws if `DATABASE_URL` is not set.
- **Rate Limiting**: `express-rate-limit` applied only to `auth.login` and `auth.forgotPassword` — 5 requests per 15 minutes per IP.

### Auth — End to End

1. **Registration**: `auth.register` creates user with `bcrypt` hash (12 rounds), generates a 6-digit OTP via `crypto.randomInt`, stores `emailOtp` + `emailOtpExpiresAt` (10 min TTL) in DB. Sends OTP via Resend if `RESEND_API_KEY` is configured, otherwise logs to console.
2. **Email Verification**: `auth.verifyEmail` checks OTP + expiry, marks `isEmailVerified = 1`, signs JWT, sets `HttpOnly` cookie (`app_session_id`, 7-day expiry).
3. **Login**: `auth.login` checks ban status → email verified → bcrypt → signs JWT → sets cookie. Blocked if `isEmailVerified = 0` or `isBanned = 1`.
4. **Session**: JWT payload = `{ userId, email, tokenVersion }`. Signed with `JWT_SECRET` (falls back to `"dev-secret-change-in-production"`). Verified on every request in `authenticateRequest()` in `auth.ts`. Token is invalidated if `user.tokenVersion` in DB doesn't match — used for logout.
5. **Logout**: `auth.logout` increments `tokenVersion` in DB (invalidates all sessions) and clears the cookie.
6. **Cookie**: `HttpOnly: true`, `SameSite: none` (HTTPS) or `lax` (HTTP), `Secure` dynamically set based on `x-forwarded-proto` header.
7. **Middleware**: `createContext()` in `context.ts` runs `authenticateRequest()` on every tRPC request and populates `ctx.user`.
8. **Protected routes**: `protectedProcedure` middleware throws `UNAUTHORIZED` if `ctx.user` is null. `adminProcedure` additionally checks `user.role === "admin"`.

### Security

| Issue | Severity | Location |
|---|---|---|
| **`POST /api/upload` is unauthenticated** | CRITICAL | `server/upload.ts:30` — No auth check. Anyone can upload files and consume Cloudinary quota or fill disk |
| **JWT secret falls back to hardcoded default** | HIGH | `server/_core/env.ts:2` — Falls back to `"dev-secret-change-in-production"` if `JWT_SECRET` is not set |
| **OTP stored in plaintext in DB** | MEDIUM | `drizzle/schema.ts:25,22` — `emailOtp` and `whatsappOtp` stored as plain VARCHAR, not hashed |
| **Review uniqueness enforced only in application code** | MEDIUM | `server/routers.ts:849-858` — No DB-level `UNIQUE(dealId, reviewerId)` constraint. Race condition possible |

| **`FRONTEND_URL` defaults to localhost:5173** | LOW | `server/routers.ts:244` — Password reset links in production would use wrong domain if env var not set |

pnpm install

```bash

cmd /c "npm run dev"

# Or directly (more reliable on Windows):
cmd /c "set NODE_ENV=development&& npx tsx server/_core/index.ts"

# Server starts on http://localhost:3000 (auto-increments if busy)
# Vite HMR is embedded — frontend hot-reloads automatically

pnpm run check
# Runs: tsc --noEmit
```

### Run Tests

pnpm run test
# Runs: vitest run

pnpm run build
# 1. Vite builds client → dist/public/

No `Dockerfile`, `railway.json`, `render.yaml`, or `nixpacks.toml` was found in the repository root. Deployment relies on platform auto-detection.

### Build Process

```
pnpm install
↓
pnpm run build
  ├── vite build  →  dist/public/  (SPA with index.html)
  └── esbuild server/_core/index.ts  →  dist/index.js  (bundled, ESM, external packages)

  └── node dist/index.js  (serves API + static SPA from same process)
```

### Environment Requirements for Production

| Variable | Value |
|---|---|
| `NODE_ENV` | `production` |
| `DATABASE_URL` | Railway MySQL connection string |

### Port Binding

The server binds to `process.env.PORT || 3000`. Railway injects `PORT` automatically.

### Image Storage

- **With Cloudinary configured**: Images stored in Cloudinary `borrowbox/` folder. URLs are permanent.
- **Without Cloudinary**: Images stored in `./uploads/` on the local filesystem. **These are lost on every redeploy** (ephemeral filesystem on Railway/Render).
